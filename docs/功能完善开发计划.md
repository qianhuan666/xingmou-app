# 《功能完善开发计划》

> 目标：在当前 Android 安全 Agent 基础上，按《原版功能清单》补齐产品功能，形成可真实使用、可专业审核、可演示验收、可逐步上线的星眸训练台。
>
> 计划版本：V1.0（2026-09-25）
>
> 范围原则：保留提示词 v1.4 的安全优先、端口隔离、人工审核和隐私最小化约束；原版依赖机构后端的能力采用“先本地闭环、后服务端扩展”的策略。

## 一、开发目标与完成定义

### 1. 产品完成定义

当以下链路可以在 `Pixel_Tablet` 或同等级平板上由测试账号完整走通，才视为“功能完善版”完成：

```text
账号登录
  → 选择授权儿童
  → 首次基线评估
  → 六域画像生成
  → 训练地图解锁课程
  → 儿童完成多题型训练
  → 结果/提示/反应时/独立度入库
  → Agent 风险与过程分析
  → 家长查看建议并完成家庭任务
  → 专业查看报表、量表和证据
  → Agent 生成方案草案
  → 专业修改、实名确认、签署生效
  → 儿童端获得新方案
  → 审计、导出、撤回和复评
```

### 2. 非目标

- 不把模型当作诊断工具，不自动下诊断、治疗或风险解除结论。
- 不在生产 APK 内长期保存可提取的 DeepSeek 主密钥。
- 不在第一轮强行恢复原版 12 面板机构治理；先完成本地单儿童/多儿童核心闭环，再接轻后端。
- 不以“代码文件存在”作为完成标准，必须有页面、数据接线、测试和验收记录。

## 二、优先级与版本路线

|---|---|---|---|

## 三、分阶段实施计划

### 阶段 A：产品数据基础与权限（P0）

**目标**：消除 `child-demo` 和固定演示数据，让所有后续能力建立在真实档案和授权边界上。

**开发任务**

1. 新增 `DomainCatalog`、`TaskCatalog`、`AssessmentCatalog`、`RehabilitationMethods` 四类正式常量，迁移六域、22 模块、15 量表和 12 方法。
2. 扩展 `ChildEntity`：化名、出生年份/年龄段、诊断转录来源、语言、ADL、状态、备注、头像颜色、六域起点。
3. 新增用户、角色、儿童授权绑定和本地会话模型；在没有后端时先实现本地测试账号和权限策略。
4. 新增儿童档案列表、搜索、状态筛选、新建、编辑、归档/删除和授权范围页面。
5. 补齐 Room DAO、索引、级联删除和迁移；所有 ViewModel 移除硬编码 `child-demo`。
6. 将 `ConsentEntity` 接入同意、撤回、用途查询和功能闸门；未同意时禁止远程 AI 与数据导出。

**验收标准**

- 可创建至少 2 名儿童并切换，数据互不串用。
- 家长只能看到被授权儿童，专业端可按授权范围查看。
- 删除儿童后，训练记录、记忆、审核、事件和远程摘要按策略清理或脱敏留痕。
- 六域、22 模块、15 量表、12 方法均可从本地知识/目录查询。

### 阶段 B：儿童基线与训练课程（P0/P1）

**目标**：把当前单一“图片配对”演示升级为可持续训练产品。

**开发任务**

1. 建立统一题目模型：`choice`、`memory`、`audio`、`observed/guided`，支持变式、目标、选项、正确答案和素材类型。
2. 为 22 模块建立本地题库和版本号；每个模块至少提供可复现的基础题与变式题。
3. 迁移彩虹岛基线 18/24 题，加入温和反馈、自动续答、稍后再玩、六域计分和画像初始状态。
4. 完善训练记录字段：提示次数、复听次数、独立完成/支持完成/未完成、暂停时长、题目版本和素材引用。
5. 实现连续正确/错误的自适应难度与支持等级；风险状态和疲劳状态必须优先于升级。
6. 实现训练地图、20 关课程、解锁/重试、每日兴趣选择、玩法排除、积分/徽章。
7. 增加儿童报告页：只展示积分、完成轮数、兴趣和鼓励性趋势，不显示排名、诊断或污名化标签。

**验收标准**

- 新儿童可完成一次基线，生成六域画像并写入 `ability_profiles`。
- 每个课程关卡有明确解锁条件，完成/重试状态可恢复。
- 至少覆盖三种游戏引擎和四种题型；随机化后 target 仍在选项中。
- “再听一遍”“给我提示”“自己完成/帮助后完成”均能正确记录。
- 连续失败、疲劳和安全风险会暂停训练，不会因为模型输出而越级。

### 阶段 C：Agent 方案与专业工作流（P1）

**目标**：让专业端从“固定草案审核”升级为有证据、可修改、可复评的专业工作台。

**开发任务**

1. 将 `AnalysisEngine` 扩展到 22 模块和六域：样本量、独立完成率、提示依赖、反应时、平台期和趋势。
2. 实现 AI 方案卡片：六域优先级、模块难度区间、目标、频率、时长、停止条件、证据来源和数据充分度。
3. 将 `PlanVersionEntity` 与接案、目标、方案、复评、结案、随访关联；补齐 `care_records` 等价 Room 模型。
4. 实现 15 量表的专业转录入口，明确“非诊断、需专业人员核对”的边界。
5. 将 12 康复方法作为可检索、可引用、可审核的知识条目。
6. 专业端增加草案差异、规则命中、知识引用、风险提示、工具调用、人工修改和签署信息。
7. 方案生效必须有专业人员身份、时间、意见和审核轨迹；旧版本只归档/失效，不覆盖。

**验收标准**

- 少于 3 条记录只能显示信息不足，不生成趋势或升级结论。
- 草案中的每条建议可追溯到训练记录、知识条目或专业人工输入。
- 模型不能确认、激活或解除风险；专业人员修改后能看到差异并留痕。
- 复评可以生成新版本，历史版本可查看，儿童端只接收当前生效版本。

### 阶段 D：家长端、报表与无障碍（P1）

**目标**：恢复原版家庭支持和可视化反馈，让家长看到“下一步怎么做”，专业人员看到“依据是什么”。

**开发任务**

1. 家长首页增加今日陪练任务、本周训练统计和安全状态三卡。
2. 实现已签署家庭任务打卡、情绪/状态日记、最近反馈和风险期禁用任务。
3. 增加 5 分钟低刺激陪练示范：准备材料、示范邀请、回应尝试、舒服结束。
4. 增加训练表现报表：正确率走势、模块练习量、独立完成率、提示依赖、反应时和最近记录。
5. 专业端增加授权儿童 KPI、多人对比（明确不用于排名/诊断）和 CSV/JSON 受控导出。
6. 完善 TalkBack contentDescription、语义角色、焦点顺序、键盘/触控目标和屏幕阅读测试。
7. 增加慢动效、柔和答题音效、试听按钮和儿童舒适设置独立入口。

**验收标准**

- 家长可以在不进入专业术语页面的情况下完成一次家庭任务和状态反馈。
- 报表中的所有指标都能回到记录明细，不出现未经校准的“能力百分比”。
- TalkBack 能按“标题→说明→操作→状态”顺序朗读三端主要页面。
- 大字体、高对比、语音关闭后，所有按钮仍可见、可操作、可恢复。

### 阶段 E：数据权利、审计与发布安全（P1/P3）

**目标**：将目前的安全骨架变成可验证的数据治理闭环。

**开发任务**

1. 实现按用途的同意页、撤回页和远程 AI 开关；撤回后禁止新的远程调用。
2. 实现授权范围导出、导入恢复、儿童级删除请求和删除结果报告。
3. 增加共享授权模型（先本地记录授权，再预留机构同步接口）。
4. 完整记录登录、训练、基线、兴趣、奖励、导出、审核、方案生效和风险操作审计。
5. 增加审计回放页：按 `runId` 展示规则、知识、工具、模型、人工决定和最终输出。
6. 增加 Agent 质量指标：完成率、工具成功率、审核接受率、草案修改率、风险拦截率、无依据判断率、响应时、步骤数、降级率、中断率。
7. 将 DeepSeek 接入抽象网关，优先使用服务端代理或短期令牌；禁止生产 APK 内置长期主 Key。
8. 完成真实网关的超时、断网、HTTP 错误、JSON 非法、费用上限和脱敏输入验收。

**验收标准**

- 抽查日志和 APK，不出现 API Key、手机号、住址或病历原文。
- 撤回远程 AI 同意后，所有远程请求被拒绝并有明确本地降级。
- 导出文件不包含密码、扫描原件和未授权儿童数据。
- 任一 Agent 运行可以按 `runId` 复盘到最终状态。

### 阶段 F：机构能力与扫描导入（P2）

**目标**：在核心闭环稳定后恢复原版机构部署能力。

**开发任务**

1. 选择“轻后端 Agent Gateway + 机构 API”方案，定义认证、同步和冲突策略。
2. 实现专业端 PDF/图片导入、哈希去重、OCR 队列、页级分类、字段置信度和证据片段。
3. 实现逐字段人工确认/排除/修改；医疗字段无论置信度多高都必须人工确认。
4. OCR 结果经画像 Agent 生成 L0–L4 画像和 22 模块参数，但只能进入 draft，签署后才下发儿童端。
5. 恢复机构治理 12 面板：儿童、内容、审核、版本、校准、组织、账号、审计、运营、共享、同意、备份。
6. 增加机构级备份、恢复、远程共享授权和会话撤销。

**验收标准**

- 同一文件重复导入不会产生重复批次。
- OCR 每个字段都有页码、置信度、证据片段和人工状态。
- 任一 OCR/Agent 结果未经专业签署不得进入儿童训练。
- 机构用户只能操作被授权组织和儿童范围。

## 五、团队分工建议

| 角色 | 负责范围 | 第一交付物 |
|---|---|---|
| Android/数据 | Room、档案、授权、迁移、导出删除 | 阶段 A 可运行数据闭环 |
| 训练/交互 | 题目模型、基线、课程、奖励、无障碍 | 阶段 B 儿童端闭环 |
| Agent/AI | 方案卡、证据、网关、指标、回放 | 阶段 C/E Agent 生产闭环 |
| 专业产品 | 量表、12 方法、临床流程、审核规则 | 阶段 C 专业工作台 |
| 测试/安全 | 红队、仪器、TalkBack、发布扫描 | 每阶段验收报告 |

## 六、阶段验收门槛

每个阶段合并前必须同时满足：

1. 功能页面可操作，不接受仅有数据类或占位按钮。
2. ViewModel、Room、Agent 事件和审计链路真实接通。
3. 至少有一个正常流程、一个异常流程和一个权限/安全流程测试。
4. 不引入新的未脱敏日志、硬编码密钥或绕过审核的状态写入。
5. 更新 `docs/开发日志.md`、测试结果和未完成项，不把“部分完成”写成“已完成”。

## 七、第一轮建议立即执行的任务

按投入产出比，建议下一轮只做以下 6 件事：

1. 迁移四类目录资产：六域、22 模块、15 量表、12 方法。
2. 做儿童档案列表/编辑/授权，并移除 `child-demo` 硬编码。
3. 完成基线 24 题和首个可解锁课程链路。
4. 将题目模型从固定图片配对扩展到 choice/memory/observed 三类。
5. 增加家长任务打卡、状态日记和训练报表最小版。
6. 建立同意/撤回/导出/删除最小闭环，再考虑真实 DeepSeek 联调。

这 6 项完成后，项目会从“安全 Agent 架构 Demo”进入“可供家庭和专业人员试用的本地产品原型”。
