## 0. 当前基线与项目结束定义

### 0.1 当前基线

当前 Git 基线：`6713743 功能开发前期准备`。

已经具备：

- Kotlin + Jetpack Compose + Room + OkHttp + Gson + Coroutines 工程。
- 三端 Compose 工作台：儿童端、家长端、专业端。
- `RiskEngine`、`PortGuard`、`TaskWhitelist`、`DifficultyController`。
- Agent Runtime、工具白名单、状态机、事件闭环、幂等和脱敏上下文。
- 本地知识检索、过程分析、专业方案 `draft → confirmed → active` 审核门。
- 儿童端 TTS、朗读、语速、音量、大字体和高对比。
- 红队单元测试、Room 仪器测试和 Compose 仪器测试。
- `Pixel_Tablet` Debug APK 安装和启动验收。

主要未完成：

- 真实儿童档案和授权体系，当前仍有固定 `child-demo` 演示路径。
- 六域、22 模块、15 量表、12 方法的完整目录和内容资产。
- 基线评估、训练地图、课程、题库、兴趣和奖励。
- 家长家庭任务、状态日记、专业临床工作流和完整报表。
- 同意/撤回/导出/删除的可操作闭环。
- 纯前端 BYOK 直连、真实 DeepSeek 联调和本地 OCR 导入。

### 0.2 项目结束定义

V1.1 才视为本项目的“第一阶段完成”，必须同时满足：

1. 新建儿童可以从基线进入课程，完成训练并恢复进度。
2. 家长可以查看建议、完成家庭任务、提交观察反馈。
3. 专业人员可以查看证据、生成/修改/签署方案并下发到儿童端。
4. 风险、权限、同意、数据删除和审计链路可验证。
5. AI 失败、网络中断和模型输出异常不会阻断本地训练。
6. 机构导入、本地账号/角色、本机共享授权与文件备份具备受控版本；跨设备同步不在本项目范围。
7. 发布 APK、测试报告、隐私说明、操作手册和演示脚本齐全。

## 1. 总体路线与版本出口

| 版本 | 目标 | 预计周期 | 版本出口 |
|---|---|---:|---|
| V0.7A | 数据、档案、授权底座 | 2 周 | 多儿童数据隔离，移除固定儿童路径 |

周期为建议值，按 1 名 Android/数据、1 名训练/交互、1 名 Agent/AI、1 名专业/测试并行估算。单人开发时按关键路径顺序执行，不并行承诺所有模块。

## 2. 执行规则

### 2.1 每个任务必须有五种结果

每个功能任务完成时必须同时提交：

1. 代码或文档变更。
2. 数据/状态流说明。
3. 至少一个正常流程测试。
4. 至少一个异常或权限测试。
5. 开发日志、验收结果和剩余风险。

### 2.2 分支和提交规范

```text
master                         可构建、可演示、可回滚
feature/<阶段>-<功能>           单功能开发分支
release/<版本>                 版本冻结与验收分支
```

提交消息使用中文，格式建议：

```text
完成V0.7A儿童档案与授权
补充V0.7B基线题目与课程测试
修复专业方案审核状态回写
完成V1.0发布安全检查
```

禁止提交：`local.properties`、真实 API Key、扫描原件、病历原文、未脱敏测试数据。

## 3. 阶段 A：V0.7A 数据、档案与授权底座

### A-1 目录资产迁移

**任务**

- 新增 `data/catalog/DomainCatalog.kt`：A–F 六域、名称、目标和展示色。
- 新增 `TaskCatalog.kt`：22 个训练模块、模块 ID、所属领域、题型、目标和白名单状态。
- 新增 `AssessmentCatalog.kt`：15 个量表的适用年龄、领域、说明和“仅专业转录”边界。
- 新增 `RehabilitationMethods.kt`：12 种方法的说明、适用场景、禁用/转介条件和来源引用。
- 将目录种子写入 Room 或版本化 Kotlin 常量，避免直接散落在 UI。

**验收**

- 目录单元测试数量、ID 唯一性、领域映射和白名单映射全部通过。
- UI 可以按领域查询模块、量表和方法。
- 每条专业建议可以引用目录 ID，而不是只保存自由文本。

### A-2 儿童档案模型

**任务**

- 扩展 `ChildEntity`：出生年份或年龄段、语言、ADL、诊断转录来源、备注、头像色、创建/归档状态。
- 新增六域起点评分和档案版本，不把诊断文本作为 AI 默认上下文。
- 新增 `ChildBindingEntity` 或等价授权表，记录用户、儿童、角色、授权开始/结束时间。
- 新增级联删除策略：训练记录、记忆、事件、审核、方案和摘要按数据权利策略处理。

**验收**

- 可创建、编辑、归档两个儿童。
- 切换儿童后儿童端、家长端、专业端数据全部切换。
- 删除/撤回后不能从普通 UI 查询到已撤回数据。

### A-3 本地角色和授权

**任务**

- 实现本地测试账号：专业人员、家长、儿童演示身份。
- 端口切换必须通过当前会话角色和儿童授权校验，而不是只依赖按钮。
- 将 `PortGuard` 扩展为权限动作检查：查看档案、训练、查看报告、生成草案、签署方案、导出、删除。
- 增加权限失败的固定提示和审计事件。

**阶段 A 出口**

```text
创建专业测试账号
→ 创建儿童 A/B
→ 授权家长只看儿童 A
→ 儿童 A 训练并写入记录
→ 切换儿童 B 不显示 A 数据
→ 撤回授权后家长无法继续读取 A
```

## 4. 阶段 B：V0.7B 基线与儿童训练主线

### B-1 统一题目模型

新增：

```text
Question
  id / version / moduleId / domain / type
  prompt / options / answer / assets
  difficulty / supportLevel / sourceRef
```

题型至少支持：

- `choice`：颜色、形状、目标搜索。
- `memory`：翻牌和配对。
- `sequence`：顺序和排序。
- `observed`：自己完成、帮助后完成、未完成。

记录字段必须包含：首次作答、正确与否、提示次数、复听次数、反应时、暂停时长、支持结果、题目版本。

### B-2 基线评估

**第一版先做 6 题最小基线，第二版扩展到 24 题。**

第一版六题覆盖：

1. 视觉辨别。
2. 颜色匹配。
3. 形状匹配。
4. 序列记忆。
5. 简单分类。
6. 情绪/生活场景选择。

**开发任务**

- 新增基线状态机：未开始、进行中、可稍后继续、完成、需重测。
- 完成后按六域生成简版 `AbilityProfileEntity`。
- 画像只描述过程表现和证据，不生成诊断结论。
- 基线支持退出、恢复和重新开始，重复开始需保留版本。

### B-3 课程地图

**第一版范围**

- 只实现 3 个模块：图片配对、颜色分类、形状匹配。
- 每个模块 3 个难度级别。
- 每关 5 个小活动，完成数和正确率达到门槛后解锁下一关。

**第二版范围**

- 扩展到 22 模块和 20 关。
- 加兴趣选择、玩法排除、积分、徽章和每日入口。

### B-4 儿童端体验

- 将固定 UI 选项改为从 `Question` 动态渲染。
- 提示和复听不显示“错误”“失败”等污名化词语。
- 风险、疲劳、连续失败优先于升级。
- 每一个训练页面都保留休息、退出和找大人入口。
- TTS 只朗读经过规则和端口校验的短句。

**阶段 B 出口**

```text
新建儿童
→ 完成 6 题基线
→ 生成六域简版画像
→ 解锁图片配对第一关
→ 完成 5 个活动
→ 中途退出并重启
→ 恢复关卡、记录和辅助设置
```

## 5. 阶段 C：V0.7C 家庭与专业最小协作

### C-1 家长端

- 首页增加今日任务、本周训练、状态提醒三卡。
- 展示已签署且允许家庭执行的任务。
- 支持完成/跳过/暂停并记录原因。
- 支持情绪、疲劳、环境变化等状态日记。
- 风险暂停期间禁用家庭训练任务，显示固定安全提示。
- 增加 5 分钟陪练示范：准备、示范、邀请、回应、结束。

### C-2 专业端

- 增加儿童档案摘要和最近训练记录。
- 增加最小报表：样本量、正确率、独立完成率、提示依赖、反应时、趋势。
- 增加 AI 草案证据卡：使用了哪些记录、知识条目、规则和工具。
- 增加草案与上一版本的差异显示。
- 确认、激活、退回均必须写入审核意见和时间。
- 下发只读取 `ACTIVE` 方案，儿童端不可读取 `DRAFT` 或 `CONFIRMED`。

### C-3 方案闭环

```text
训练达到数据阈值
→ AnalysisEngine 分析
→ Agent 生成 draft
→ JsonValidator + TaskWhitelist + DifficultyController
→ ReviewRequest
→ 专业修改/确认
→ confirmed
→ 专业签署
→ active
→ 儿童端读取新版本
```

**阶段 C 出口**

- 一名儿童完成训练后，家长提交观察。
- 专业端查看记录和证据，生成草案。
- 专业人员修改、确认、签署。
- 儿童端下一次训练读取新方案。
- 全过程可以按 `runId` 和 `planId` 回放。

## 6. 阶段 D：V0.8 完整家庭、专业和无障碍体验

### D-1 内容资产扩展

- 完成 22 模块题库，每模块至少有基础题、变式题和停止条件。
- 完成 15 量表转录入口和专业提示。
- 完成 12 方法库的知识条目、来源和适用边界。
- 所有内容具备版本号、审核状态和来源引用。

### D-2 临床/专业工作流

新增等价于原版的阶段记录：

```text
接案 → 目标 → 方案 → 复评 → 结案 → 随访
```

- 目标必须是可观察、可度量的训练过程目标。
- 复评创建新版本，不覆盖历史方案。
- 结案和随访只允许专业人员操作。
- 诊断字段只做专业转录，必须保留来源和日期。

### D-3 报表和可视化

- 儿童端：积分、完成轮数、兴趣和鼓励性趋势。
- 家长端：本周任务、完成率、状态变化和建议。
- 专业端：六域、模块、正确率、独立度、提示依赖、反应时、样本量。
- 所有图表都能点击回到记录明细。
- 明确显示“训练表现不等于能力评估或医学诊断”。

### D-4 无障碍

- TalkBack 内容描述、状态播报和焦点顺序。
- 最小触控目标 48dp，儿童主要目标 64dp。
- 大字体、高对比、慢动效、语音开关和试听。
- 横屏平板和竖屏窄屏均完成测试。

**阶段 D 出口**

- 家长可独立完成一次家庭任务和日记。
- 专业人员可以完成一次复评并创建新版本。
- TalkBack 可完成儿童端核心训练流程。
- 报表指标与 Room 记录逐项一致。

## 7. 阶段 E：V1.0 纯前端 BYOK AI、数据权利与试点发布

### E-1 设备端 API Key 设置与 DeepSeek 直连

运行架构：

```text
Android App
  → 专业端“机构 API Key”设置（使用者自行输入，设备本地保存）
  → 当前儿童授权、远程 AI 同意、本地脱敏和超时/费用闸门
  → DeepSeek
  → JSON/来源/端口校验、人工审核或本地安全降级
```

Android 客户端必须负责：

- API Key 不写入源码、Git、BuildConfig 或 APK 常量；允许使用者自行输入并保存在当前设备。使用者接受设备端 Key 可被提取的风险。
- 请求前检查本地用户/儿童绑定和远程 AI 同意；无 Key 或无同意时使用本地安全模式。
- 过滤手机号、身份证、住址、病历原文和未授权字段。
- 超时、暂态重试、断网、HTTP 错误、输入长度和输出 token 上限；客户端费用估算仅供提示，不能保证真实账单上限。
- 响应 JSON 校验、来源校验、端口裁剪和降级。
- 保存不含 Key/请求原文的调用摘要、模型版本、耗时和错误类别。

### E-2 数据权利

- 按用途记录同意：训练、AI、共享、导出、研究/试点。
- 撤回后禁止新的对应操作。
- 支持儿童范围导出 JSON/CSV。
- 支持儿童级删除请求和删除结果报告。
- 导出不含密码、扫描原件、未授权儿童和 API Key。

### E-3 Agent 质量与审计

新增 `AgentMetrics` 或等价统计：

- 任务完成率。
- 工具调用成功率。
- 越权拦截率。
- 风险拦截率。
- 无依据判断率。
- JSON 校验失败率。
- 降级触发率。
- 平均步骤数和响应时间。
- 审核接受率、修改率和用户中断率。

### E-4 真实联调门槛

真实 DeepSeek 联调必须满足：

1. 使用专用测试儿童和脱敏数据。
2. 用户明确同意数据出境。
3. 在设备端设置请求超时、长度和输出 token 上限；实际余额、费用上限和账单由使用者在 DeepSeek 平台管理。
4. 使用专用测试 Key；测试后撤销/轮换。
5. 不把真实返回原文提交 Git 或写入普通日志。

**阶段 E 出口**

- AI 失败不会影响本地训练。
- 所有远程请求都能关联用户同意、儿童授权和 `runId`。
- APK 和 Git 扫描不出现预置密钥及敏感身份数据；运行时由使用者填写的 Key 不属于 APK 静态内容。
- 完成内部试点发布包和回滚包。

## 8. 阶段 F：V1.1 本地机构扩展

### F-1 账号与组织

- 手机号/邮箱账号、密码哈希、失败锁定、会话撤销。
- 组织、班级、专业人员和儿童授权关系。
- 角色与数据范围仅在本机校验；不宣称具备服务端强制 RBAC 或跨设备身份保证。

### F-2 扫描档案导入

```text
上传 PDF/图片
→ 哈希去重
→ 分页 OCR
→ 页面分类
→ 字段抽取
→ 证据/置信度展示
→ 专业逐字段复核
→ draft 画像/题目
→ 专业签署
→ 下发儿童端
```

医疗字段无论 OCR 置信度多高，都不能自动入档或自动生效。

### F-3 机构治理

按使用频率分批恢复：

1. 儿童/授权/账号。
2. 内容/版本/审核。
3. 审计/运营/校准。
4. 共享/同意/备份。

### F-4 本地备份与恢复策略

- Room 是本机权威数据源，不建设跨设备同步队列。
- 文件备份包含格式版本、导出时间和校验值；恢复前预览并由使用者确认。
- 同一儿童的导入冲突不静默覆盖，进入专业/管理员本机处理流程。
- 风险、审核和删除事件采用追加事件，不允许普通字段覆盖历史。

**阶段 F 出口**

- 机构测试账号可在授权范围内导入、复核、签署和下发一份档案。
- 内容版本变更有审核和回滚。
- 共享、备份和删除都有审计证据。

## 9. 关键数据模型增量

| 模块 | 当前基础 | 需要新增/扩展 |
|---|---|---|
| 用户 | 无完整账号 | `UserEntity`、`SessionEntity`、`ChildBindingEntity` |
| 儿童 | `ChildEntity` 简化字段 | 档案版本、授权、六域起点、档案来源 |
| 训练 | `TrainingRecordEntity` 基础字段 | 题目版本、提示/复听、支持结果、暂停时长、素材引用 |
| 课程 | 无 | `QuestionEntity`、`CurriculumLevelEntity`、`RewardEntity` |
| 评估 | `AbilityProfileEntity` 骨架 | 基线会话、量表转录、复评记录、证据 |
| 家庭 | 无完整模型 | `HomeTaskEntity`、`HomeFeedbackEntity` |
| 专业 | 方案/审核已有 | `CareRecordEntity`、签署信息、草案差异 |
| 同意 | `ConsentEntity` 骨架 | 用途、版本、撤回原因、远程调用闸门 |
| 权利 | 无完整流程 | `DataRequestEntity`、导出批次、删除结果 |
| 审计 | Agent 追踪已有 | `AuditLogEntity`、指标、回放索引 |
| 机构 | 未开始 | 组织、账号、内容版本、共享、备份 |
| OCR | 未开始 | 导入批次、页、字段、复核和提交记录 |

## 10. 测试计划

### 10.1 单元测试

- 目录唯一性和白名单。
- 基线计分和六域汇总。
- 题目随机化、难度和支持等级。
- 课程解锁、奖励去重和进度恢复。
- 风险优先级、否定词和暂停。
- 方案状态机和签署约束。
- 同意、撤回、导出、删除策略。
- 设备直连前置策略的脱敏、超时和降级。

### 10.2 Room 仪器测试

- 多儿童隔离。
- 迁移和回滚前后数据。
- 事务写入训练/风险/审核。
- 删除级联和撤回后的查询。
- 本地备份恢复的幂等和冲突处理。

### 10.3 Compose 仪器测试

- 登录/角色/儿童切换。
- 基线完成和退出恢复。
- 课程解锁和训练记录。
- 家庭任务和日记。
- 专业草案、确认、签署、退回。
- 大字体、高对比、TalkBack 语义。

### 10.4 端到端验收

固定使用以下三条脚本：

**脚本 1：儿童训练**

```text
创建儿童 → 基线 → 第一关 → 连续错误触发暂停 → 恢复 → 完成活动 → 查看记录
```

**脚本 2：家庭—专业协作**

```text
家长观察 → 检索建议 → 家庭打卡 → 专业查看 → 生成草案 → 修改 → 签署 → 儿童读取新方案
```

**脚本 3：安全与数据权利**

```text
输入高危文本 → SAFETY_STOP → 不调用模型/工具
撤回 AI 同意 → 远程请求被阻断 → 导出授权数据 → 删除儿童 → 查询不到已删数据
```

## 15. 总结

本计划的执行原则只有三条：

1. 先完成一条真实可用的“儿童—家长—专业”闭环，再扩展内容数量。
2. 先让数据、权限、审核和安全可验证，再接入真实 AI。
3. 每个阶段必须有可运行产物和明确出口，未达到出口就不进入下一阶段。

按照本计划执行，当前项目将从阶段性 Agent 安全 Demo，逐步变成可试用的训练产品、可受控发布的 AI 应用，最后再扩展到机构级平台。
