# 原版「启智训练台」功能实现清单

> 源码对象：`QizhiTrainingPlatform-Portable`（便携版交付包）
> 核对方式：逐文件通读 `js/`（33 个模块）、`backend/schema.sql`、`index.html`、启动脚本与第三方声明。
> 本文档只记录**已实现**的功能，每条附**技术简要**，作为安卓端迁移的完整功能基线。
> 更新时间：2026-09-25

---

## 1. 总体架构与技术栈

| 层 | 实现 | 技术简要 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS，33 个 JS 模块 | 无框架；单页 `index.html` + 33 个 `<script>`；全局函数式状态 + 逐层 monkey-patch 扩展（`const x=renderTrain; renderTrain=function(){...}`） |
| 本地后端 | Python 3.13 + aiohttp | 打包为 `QizhiTrainingPlatform.exe`（PyInstaller），启动脚本 `start-platform.ps1/.bat` 拉起 Ollama 与 exe |
| 数据库 | SQLite（WAL 模式） | `backend/schema.sql` 定义 30+ 张表，主库为机构侧权威数据 |
| 浏览器镜像 | `localStorage` | 前端内存 + localStorage 双写，作离线镜像与即时响应层 |
| 本地 AI | Ollama + `qwen3:0.6b` + CrewAI | `LEVEL_AGENT_CREWAI=1`、`LEVEL_AGENT_MODEL=ollama/qwen3:0.6b`；失败回退到内置规则引擎 |
| 文档识别 | RapidOCR / ONNX / OpenCV / PyMuPDF | 历史扫描 PDF 逐页 OCR、分类、字段抽取（`_internal` 目录携带运行库） |

**数据分层策略**：前端数组（`children/records/plans/tasks`）即时读写 → 后端 REST 同步 → SQLite 落库；后端不可用时降级为纯浏览器本地模式（`BACKEND_API.available` 开关）。

## 2. 身份、角色与权限体系

| 功能 | 技术简要 |
|---|---|
| 三角色模型 | `config.js` 定义 `teacher`(康复专业人员)/`parent`(家长)/`child`(儿童)，`PERMS` 声明每个角色的能力位（manage/train/viewReport/viewAI/settings/accounts/org/audit/content） |

| 端口隔离 | 儿童端裁剪诊断、风险、排名、专业术语；家长端无管理/账号能力；专业端才可见治理入口 |
| 角色入口切换 | 登录页可选 child/parent/teacher 三身份进入，同一手机号可绑定多身份 |

| 功能 | 技术简要 |

## 6. 训练引擎与自适应难度

| 功能 | 技术简要 |
|---|---|
| 统一题目模型 | `question-logic-v2.js`：`qChoice/qMemory/qAudio/qObserved` 四种题型；`MODULE_ACTIVITY_BANK` 为 22 模块内置本地题库（每题 3 个变式） |
| 难度自适应 | `makeAdaptive()`：连 2 对升 1 级、连 2 错降 1 级，范围 1–5；`updateDifficulty()` 在统一答题器内实现 |
| 起点难度推断 | `moduleDifficultyFor()`：优先已签署方案的模块难度 → 已生效评审 → 六域画像分（`ceil(score/22)`）→ 近 6 条加权表现（firstCorrect=1, correct=0.65） |
| 选项随机化 | `shuffledQuestionChoices()`：洗牌 + 按难度裁剪选项数（难度1→2选项，2→3选项，否则全量），保证 target 必在选项内 |
| 分级提示 | 每题支持「再听一遍」（repeatCount）与「给我提示」（hintCount，禁用一个错误选项）；`promptLevel` 记录 0/1/2 |
| 反应时与独立度 | 每答记录 `reactionMs`（扣除暂停）、`firstCorrect`（首答且无提示）、`supportOutcome`（independent/supported/not-completed） |
| 观察型任务 | spoken/guided 题型按「自己完成/帮助后完成/还没完成」记录，避免仅一个"完成"按钮天然满分 |

## 7. 儿童首次基线评估（彩虹岛）

| 功能 | 技术简要 |
|---|---|
| 游戏化起点评估 | `onboarding-assessment.js`：`BASELINE_GAMES` 18 题 → `baseline-logic-v2.js` 扩到 24 题，覆盖六域多个构念（视觉辨别、颜色、序列记忆、工作记忆、分类推理、语言理解、情绪识别、共同注意、生活工具等） |
| 儿童主动进入 | 只有 child 角色且无 `completed` 基线记录时，`enterApp()` 延时 120ms 自动拉起旅程；家长/专业账号不触发 |
| 温和反馈 | 答对亮色庆祝动画、答错柔和成长型语言（"谢谢你认真试一试"），连对 streak 徽章；不显示"错" |
| 计分 | `scoreBaselineDomainV2()`：正确=1、帮助后完成=0.5、有提示=0.55、有复听=0.8，按域求百分比 |
| 自动续答 | 每题 2.2 秒后自动进入下一题，儿童可点"继续"或"稍后再玩"（可退出） |
| 语音与音效 | `speakBaseline()`（Web Speech API 中文）+ `playBaselineAnswerSound()`（Web Audio 合成柔和上行/下行音，非高频突发） |
| 画像生成 | 完成后 `buildIntegratedProfile()` 生成六域画像，写 `ability_profiles` 表；AI 叙述失败不阻塞画像落库（先写 generating 状态） |

## 8. 训练地图与课程（儿童端）

| 功能 | 技术简要 |
|---|---|
| 闯关地图 | `childAdventureOrder()`：按六域画像分从低到高排序，串成多邻国式关卡路径；`getLevelState()` 判定 passed（≥3 次且正确率≥60%） |
| 关卡解锁 | 未通过的下一关为 current，其后全部 locked；重试关显示上次正确率 |
| 20 关课程 | `level-curriculum.js` `CURRICULUM_LEVEL_TITLES` + `CURRICULUM_ICON`；`buildLocalCurriculum()` 按域弱→强排序，每关 5 个小活动，`passRule:{minCompleted:5,minAccuracy:.6}` |
| 兴趣入口 | `rubric-alignment.js` `RUBRIC_INTEREST_CHANNELS`（颜色/图形/声音），每日首次进入弹出"今天想玩什么？"，选择后按兴趣链路排序关卡 |
| 玩法偏好排除 | `openCurriculumPreferences()` 允许儿童排除不想玩的题型（至少留 2 种），`saveCurriculumExclusions()` 持久化 |
| 积分奖励 | `recordRubricReward()`：完成一轮 +10 积分（按 recordIds 去重防重复发放），50 分一枚徽章；`rubricRewardSummary()` 汇总 |
| 儿童端显示 | 报告页显示积分/完成轮数/常选兴趣，不显示排名与诊断 |

## 9. AI 方案引擎

| 功能 | 技术简要 |
|---|---|
| 本地启发式分析 | `ai.js` `analyze()/genPlan()`：基于正确率/趋势/平台期（plateau）做难度梯度建议，纯规则、非联网大模型 |
| 六域方案 | `question-logic-v2.js` 增强 `genPlan`：为 22 模块逐个计算 `moduleDifficulty`，为六域计算 `domainStats`（近 18 条独立完成率） |
| AI 方案 Tab | `ai-view.js`：六域卡片 + 难度区间 + 独立完成率 + 样本量；专业端可"重新生成方案"（写入 reviews 待复核） |
| 证据充分度 | `ui-role-experience.js` 为每条 AI 建议标注样本量与数据充分度（样本≥12 较充分 / 6–11 有限 / <6 不足），不用未校准的置信度百分比 |
| 儿童画像叙述 | `profile-ai.js` `generateChildProfileNarrative()`：优先 `/api/ai/profile` 后端 → 浏览器直连 Ollama `qwen3:0.6b` → 内置 `SafeProfileEngine` 兜底；只传六域分数不传个人身份 |

## 14. 历史扫描档案批量导入（仅专业端本机）

| 功能 | 技术简要 |
|---|---|
