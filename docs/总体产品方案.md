# 星眸训练台总体产品方案

> 具体到任务、版本、验收命令和项目结束出口的执行版，请参阅：[项目结束执行开发计划.md](项目结束执行开发计划.md)。

> 版本：V1.0
>
> 日期：2026-09-25
>
> 目标（2026-09-26 架构决议）：将当前“安全 Agent 架构 Demo”建设为纯前端 Android 单机训练产品。机构使用者可在设备上填写自己的 DeepSeek API Key 直连；不建设或依赖自有服务端。

## 一、总体判断

当前项目已经具备安全规则、Agent Runtime、Room 数据层、三端 Compose 工作台、TTS 和自动化测试，适合作为产品底座；但还没有完成原版产品最关键的业务资产和用户闭环。

后续应采用“核心闭环优先、机构能力后置、AI 受控接入”的路线，不建议同时开发 OCR、治理后台、全量账号和所有课程，避免项目再次陷入功能铺摊子但无法验收的状态。

最终产品应形成以下闭环：

```text
用户/专业人员登录
  → 选择被授权儿童
  → 首次基线评估
  → 形成六域过程画像
  → 进入课程地图和训练任务
  → 记录正确率、提示、反应时、独立度
  → 规则引擎做风险与难度控制
  → Agent 检索知识、整理证据、生成草案
  → 专业人员审核、修改、签署
  → 家长执行家庭支持任务
  → 复评、版本迭代、审计和数据权利管理
```

## 二、推荐目标架构

### 1. 产品架构

```text
Compose 三端口
  ├─ 儿童端：基线、课程、训练、语音、舒适设置
  ├─ 家长端：观察、家庭任务、状态反馈、建议、报告
  └─ 专业端：档案、评估、分析、方案、审核、审计
          ↓
ViewModel / UseCase 层
          ↓
领域与安全层
  ├─ RiskEngine / PortGuard / TaskWhitelist
  ├─ TrainingEngine / CurriculumEngine / AnalysisEngine
  └─ ConsentManager / DataRightsManager
          ↓
Agent Runtime
  ├─ ContextAssembler：脱敏最小上下文
  ├─ ToolRegistry：工具白名单和端口权限
  ├─ Orchestrator：有限步骤、超时、幂等、降级
  ├─ ReviewGate：专业审核门
  └─ DecisionTrace：规则、知识、工具、模型、人工轨迹
          ↓
数据与外部能力
  ├─ Room：本机权威数据源和离线安全运行
  ├─ 本地 API Key 设置：使用者运行时填写/清除
  └─ DeepSeek 直连：经本地同意、儿童授权、脱敏和 JSON 校验闸门
```

### 2. 关键架构决策

| 决策 | 方案 |
|---|---|
| 数据策略 | 单机 Room 为权威数据源；无网络时可训练、暂停、记录和查看本地已审核知识；网络仅用于获授权的 DeepSeek 直连 |
| AI 接入 | 使用者在专业端机构配置中自行填写 Key；不预置到 APK。设备端 Key 存储存在可提取风险，由使用者接受 |
| 安全边界 | 风险、难度、权限、审核和数据写入由确定性代码控制，模型只能提出结构化建议 |
| 方案生效 | `draft → confirmed → active`，必须有专业人员身份、意见和时间戳 |
| 医疗边界 | 平台只做训练过程支持和资料转录，不做诊断、治疗或自动风险解除 |
| 扩展策略 | 始终保持纯前端；机构能力以本机角色、导入导出和文件备份实现，不直接复刻原版服务端后台 |

## 三、产品分层与版本目标

### V0.7：可用本地产品

这是下一阶段的主目标，不追求功能最多，追求真实可用。

**必须完成：**

- 儿童档案、授权关系和本地角色；移除 `child-demo` 硬编码。
- 六域、22 模块、15 量表、12 方法的目录与种子数据。
- 首次基线评估和六域画像。
- 多题型训练、题目版本、提示/复听/独立度记录。
- 基础课程地图、解锁、重试和儿童友好报告。
- 同意、撤回、导出、删除最小闭环。

### V0.8：家庭—专业协作产品

- 家长首页、家庭任务打卡、状态日记和陪练示范。
- 专业分析报表、量表转录、方法库和临床阶段记录。
- 六域/模块 AI 方案卡、证据抽屉、草案差异和人工修改。
- 复评、新版本方案和签署后下发儿童端。
- TalkBack、焦点顺序、慢动效和完整舒适设置。

### V1.0：受控试点版本

- 设备端 BYOK 设置、本地身份/儿童授权、远程 AI 同意、超时/估算费用闸门和调用摘要审计。
- DeepSeek 真实联调：超时、断网、非法 JSON、错误码、降级。
- 完整审计回放和 Agent 质量指标。
- 平板、真机、弱网、重启、数据恢复和发布包扫描。

### V1.1：机构扩展版本

- PDF/OCR 历史档案导入。
- 机构、组织、账号、内容版本、校准、共享和备份治理。
- 本地导入冲突处理、机构级本机审计和运营看板；不包含多端同步。

## 四、三条并行工作线

### 工作线 A：核心业务闭环

负责儿童档案、目录资产、基线、训练、课程、家长和专业页面。这条线决定产品是否“能用”。

### 工作线 B：Agent 与数据安全

负责 Agent 工具、模型网关、脱敏、同意、审计、指标、回放和发布安全。这条线决定产品是否“可信”。

### 工作线 C：机构扩展

负责本地 OCR、治理工作台、本机共享授权和文件备份。这条线在 A/B 形成稳定验收后再投入，避免提前拖慢主线。

## 五、阶段实施顺序

### 阶段 1：数据与权限底座

**顺序：**

1. 四类目录资产迁移。
2. 儿童档案和授权模型。
3. 本地测试账号和端口权限。
4. Consent/撤回/删除策略。
5. Room 迁移与 ViewModel 接线。

**阶段出口：**可以创建两个儿童，分别训练、查询、授权和删除，数据不会串用。

### 阶段 2：儿童训练主线

**顺序：**

1. 题目模型和题库。
2. 基线 24 题。
3. 六域画像。
4. 三种以上游戏和多题型训练。
5. 课程地图、解锁、兴趣和奖励。
6. 儿童报告与无障碍。

**阶段出口：**新儿童可从基线进入第一关，完成训练并在重启后恢复进度。

### 阶段 3：家庭与专业闭环

**顺序：**

1. 家长任务和状态日记。
2. 报表和数据充分度。
3. 量表转录和方法库。
4. AI 方案卡和证据链。
5. 临床阶段记录、复评和版本化。
6. 专业修改、确认、签署和下发。

**阶段出口：**一名儿童可以完成“训练—家庭反馈—专业审核—新方案下发”完整链路。

### 阶段 4：纯前端 BYOK AI 与数据治理

**顺序：**

1. 建立设备端“机构 API Key 设置”，由使用者自行填写或清除。
2. 直连接入 DeepSeek，所有请求经过本地儿童授权、同意和脱敏闸门。
3. 完成错误/超时/断网/费用限制。
4. 完成审计回放和质量指标。
5. 完成导出、删除、撤回和发布扫描。

**阶段出口：**真实 AI 失败不会阻断训练，任何建议都能回溯来源并由规则/人工接管。

### 阶段 5：机构能力

仅在阶段 1–4 稳定后启动：本地 OCR 导入、机构治理、本机共享授权、文件备份和运营。

## 六、Agent 统一工作流

所有三端口统一采用以下处理链：

```text
事件进入
  → 身份/儿童授权检查
  → RiskEngine 安全判断
  → ConsentManager 数据出境判断
  → ContextAssembler 脱敏组装
  → Agent 选择白名单工具
  → ToolRegistry 授权/幂等/参数校验
  → 执行并保存摘要
  → JsonValidator 校验输出
  → PortGuard 裁剪展示
  → 需要时进入 ReviewGate
  → 写入 DecisionTrace 和审计日志
  → 失败时 SafeResponses 降级
```

Agent 明确不能做的事：

- 直接写 Room 或绕过 DAO。
- 自动确认或激活方案。
- 自动解除风险暂停。
- 生成诊断、治疗或虚构来源。
- 读取未授权儿童、手机号、病历原文或机构数据。

## 七、团队与迭代方式

建议按 4 个角色组织，每个迭代 1–2 周：

| 角色 | 主要职责 |
|---|---|
| Android/数据 | Room、档案、授权、迁移、导出删除、页面接线 |
| 训练/交互 | 题库、基线、课程、儿童体验、无障碍 |
| Agent/AI | 工具、网关、提示词、审核、指标、回放 |
| 专业产品/测试 | 量表、方法、临床流程、红队、验收和试点反馈 |

每个迭代必须交付：

1. 一个用户可操作的完整子流程。
2. 一个正常流程测试、一个异常流程测试、一个权限/安全测试。
3. Room 和 Agent 真实接线，不接受只写模型类。
4. 更新开发日志和未完成列表。
5. 平板模拟器验收记录。

## 八、项目验收指标

### 功能指标

- 新儿童从基线到第一关的完成率。
- 训练记录写入成功率和重复写入率。
- 家长任务完成率。
- 专业草案审核接受率和修改率。
- 方案版本从草拟到签署的完成率。

### Agent 指标

- 工具授权通过率。
- 越权调用拦截率。
- 风险拦截率。
- 无依据判断率。
- JSON 校验失败率。
- 降级触发率。
- 平均步骤数、响应时间和用户中断率。

### 安全指标

- 未授权儿童数据泄露次数为 0。
- API Key 进入 Git 或发布包扫描结果为 0。
- 风险状态下继续训练次数为 0。
- 未经专业审核生效的方案数为 0。
- 导出文件包含未授权数据的次数为 0。

## 九、近期 10 个工作日建议

### 第 1–2 天

- 确认 V0.7 范围和验收样例。
- 整理六域、22 模块、15 量表、12 方法的原版资产。
- 建立功能 ID、Room 字段和页面入口映射表。

### 第 3–5 天

- 实现儿童档案、授权关系和本地测试账号。
- 接通儿童列表、切换、编辑和删除。
- 移除所有 `child-demo` 读写路径。

### 第 6–8 天

- 实现题目模型、第一批题库和基线流程。
- 将图片配对改为可配置题目，不再把题目写死在 UI。
- 将基线结果写入 `ability_profiles`。

### 第 9–10 天

- 建立第一条课程解锁链路。
- 增加家长任务/状态日记最小页面。
- 执行多儿童、重启恢复、删除清理和三端回归测试。

## 十、最终建议

项目当前最合理的定位是：

> 先做成一个安全、可审计、可离线运行的特殊儿童训练核心产品，再逐步接入真实 AI 和机构服务；不要先追求“功能清单全部搬完”，而要先完成一条真实儿童从基线、训练、家庭反馈到专业方案的可复用闭环。

只要 V0.7 和 V0.8 按上述顺序完成，现有 Agent 安全底座就能转化为真正有产品价值的能力；V1.0 再解决生产 AI、数据治理和发布问题，V1.1 才进入机构级扩展。
