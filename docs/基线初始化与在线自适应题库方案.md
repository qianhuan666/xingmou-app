# 基线初始化与在线自适应题库方案

版本：V1.1

适用范围：星眸训练台 Android 端正式训练题库与专业方案联动。

## 一、方案目标

建立“起点小测决定训练起点、作答表现调整下一题难度、专业方案控制训练方向”的题库策略。

目标包括：

- 无专业方案时，根据起点小测结果分配模块和初始难度；
- 有生效专业方案时，优先采用方案指定模块、难度和支持等级；
- 正式训练中答对提升难度，答错降低难度；
- 每个模块支持 5 个难度等级、每级 3 个题目变式；
- 所有题目、难度变化和方案版本均可追踪和回放；
- 避免一次训练加载全部题目，控制儿童的单次训练负担。

## 二、策略优先级

儿童端正式训练按照以下顺序确定策略：

```text
当前生效专业方案
→ 起点小测能力画像
→ 近期训练表现自适应
→ 默认难度 L1
```

起点小测本身不受专业方案限制，用于建立儿童训练基线。

专业方案草案、已退回方案和已归档方案不得影响儿童端；只有 `active` 状态的方案可以下发训练策略。

## 三、基线分配规则

### 3.1 能力域与训练模块

| 能力域 | 模块 | 训练方向 |
|---|---|---|
| A 注意感知觉 | P01～P04 | 颜色、形状、视觉搜索、听觉注意 |
| B 记忆 | M01～M04 | 物品配对、翻牌记忆、序列回忆、工作记忆 |
| C 执行逻辑 | E01～E04 | 因果、分类、数量、计划顺序 |
| D 语言沟通 | L01～L04 | 图片命名、句子表达、指令理解、AAC |
| E 社会情绪 | S01～S03 | 情绪识别、轮流共同注意、社交规则 |
| F 生活动作 | D01～D03 | 生活步骤、精细动作、模仿节律动作 |

### 3.2 分数到难度

将每个能力域分数标准化为 0～100，再映射到初始难度：

| 基线分数 | 初始难度 | 说明 |
|---:|---:|---|
| 0～39 | L1 | 目标明显、选项少、提示充分 |
| 40～59 | L2 | 轻度干扰、逐步减少提示 |
| 60～74 | L3 | 选项增加、加入相似干扰 |
| 75～89 | L4 | 增加延迟、多步骤或规则切换 |
| 90～100 | L5 | 新情境迁移、低提示完成 |

分数越低，训练初始难度越低。分数相同的能力域按照模块固定顺序进入训练，保证结果可复现。

### 3.3 无专业方案时的模块顺序

1. 按能力域分数从低到高排序；
2. 优先训练当前最弱能力域；
3. 在该域内按模块顺序依次训练；
4. 当前域完成后进入下一个能力域；
5. 22 个模块全部完成后显示课程完成，不伪造新的进行中模块。

例如：

```text
B 域 → M01 → M02 → M03 → M04
F 域 → D01 → D02 → D03
C 域 → E01 → E02 → E03 → E04
```

## 四、在线自适应规则

### 4.1 普通选择题

每道题完成后立即计算下一题难度：

| 作答结果 | 难度变化 |
|---|---:|
| 正确且首次独立完成 | +1 |
| 错误 | -1 |
| 正确但使用提示 | 保持 |
| 无效选择 | 不记录，不调整 |

难度必须限制在 L1～L5：

```kotlin
nextDifficulty = (currentDifficulty + delta).coerceIn(1, 5)
```

示例：

```text
L2 答对 → 下一题 L3
L3 答错 → 下一题 L2
L5 答对 → 继续 L5
L1 答错 → 继续 L1
```

### 4.2 观察题

观察题没有普通意义上的正确答案，只记录完成程度：

| 完成结果 | 难度变化 |
|---|---:|
| 自己完成 | +1 |
| 帮助后完成 | 保持 |
| 还没完成 | -1 |

观察题仍然使用固定选项：

```text
自己完成 / 帮助后完成 / 还没完成
```

### 4.3 支持等级

难度和支持等级分别调整：

- 连续表现良好：难度提高，支持等级逐步降低；
- 使用提示或出现错误：难度保持或降低，支持等级提高；
- 出现疲劳、拒绝或安全风险：立即暂停，不自动升难度。

## 五、题目选择策略

每个模块的正式题库结构：

```text
5 个难度等级 × 每级 3 个稳定变式
```

题目选择流程：

1. 确定当前 `moduleId`；
2. 读取当前模块有效难度；
3. 优先选择当前难度的未完成题；
4. 当前难度无可用题时，选择相邻难度；
5. 同一训练会话内避免重复题目；
6. 记录题目 ID、题目版本和难度变化原因。

推荐抽题比例：

```text
70% 当前难度
20% 低一级巩固
10% 高一级挑战
```

抽题必须使用稳定的题目 ID。随机策略应使用儿童 ID、模块 ID 和训练会话 ID 作为种子，保证审计回放时能够复现。

## 六、专业方案联动

专业方案提供训练方向和起始条件，不完全锁死后续难度。

示例：

```json
{
  "module_id": "M02",
  "difficulty": 3,
  "support_level": "L1",
  "observable_goal": "记住并匹配相同图片"
}
```

训练过程：

```text
开始 L3
→ 答对：L4
→ 答错：L3
→ 连续答错：L2
```

方案变更时：

- 新方案版本采用新的模块和起始难度；
- 历史题目和训练记录不被改写；
- 草案和退回版本不影响儿童端；
- 方案版本写入训练审计记录。

## 七、数据持久化设计

当前难度不能只存于内存状态，否则应用重启后会丢失自适应进度。建议增加 Room 表 `module_adaptive_states`：

| 字段 | 说明 |
|---|---|
| `childId` | 儿童 ID |
| `moduleId` | 模块 ID |
| `baselineVersion` | 使用的基线版本 |
| `currentDifficulty` | 当前难度 |
| `currentSupportLevel` | 当前支持等级 |
| `correctStreak` | 连续正确次数 |
| `errorStreak` | 连续错误次数 |
| `lastQuestionId` | 最近题目 ID |
| `updatedAt` | 更新时间 |

训练记录还应保留：

- 题目 ID 和题目版本；
- 实际作答难度；
- 基线版本；
- 专业方案 ID 和版本；
- 支持等级和提示等级；
- 难度变化原因。

## 八、儿童端展示

儿童端不展示复杂的医学或能力分数，只显示鼓励性反馈：

- “这一题完成啦，下一题会有一点点挑战。”
- “这次我们慢一点，换一道更容易的。”
- “你已经在这个关卡里完成了 3 题。”

家长端和专业端可以查看：

- 当前模块；
- 当前难度；
- 难度变化趋势；
- 独立完成率；
- 提示依赖；
- 方案版本和训练记录关联。

## 九、安全和停止条件

以下情况不得自动升难度：

- 出现连续错误；
- 出现疲劳、拒绝或情绪明显波动；
- 触发安全风险；
- 当前题目结果无效或数据不完整；
- 训练记录保存失败。

发生安全暂停时，停止当前训练并保留已经完成的记录，等待成人或专业人员处理。

## 十、开发实施顺序

### 阶段 1：基础策略

- 新增 `BaselineDifficultyPolicy`；
- 将六域基线分数转换为 22 模块初始难度；
- 建立弱项优先的模块队列。

### 阶段 2：自适应引擎

- 新增 `AdaptiveDifficultyEngine`；
- 实现正确升级、错误降级、边界限制；
- 接入观察题完成度和支持等级。

### 阶段 3：题目选择器

- 新增 `ModuleQuestionSelector`；
- 支持当前难度、相邻难度和变式去重；
- 支持可复现抽题。

### 阶段 4：持久化

- 新增 `module_adaptive_states`；
- 保存模块当前难度和连续表现；
- 记录基线版本和方案版本。

### 阶段 5：端内联动

- 接入儿童端关卡播放器；
- 接入家长端训练概览；
- 接入专业端方案和难度回放。

### 阶段 6：验收测试

- 基线分数映射测试；
- 正确升级测试；
- 错误降级测试；
- L1/L5 边界测试；
- 观察题完成度测试；
- 应用重启恢复测试；
- 专业方案优先级测试；
- 题目不重复和审计回放测试。

## 十一、验收标准

- 无专业方案时，训练顺序由基线弱项决定；
- 有专业方案时，方案模块和起始难度优先；
- 答对后下一题难度最多提高 1 级；
- 答错后下一题难度最多降低 1 级；
- 难度始终在 L1～L5；
- 观察题不使用普通正确率判分；
- 22 个模块均可进入并能找到对应难度题目；
- 应用重启后能恢复每个模块的当前难度；
- 历史训练记录可关联题目、基线和专业方案版本；
- 任何安全暂停都不会触发自动升难度。
