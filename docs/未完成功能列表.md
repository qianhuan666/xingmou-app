# 星眸训练台未完成功能列表

> 对照基线：`docs/原版功能清单.md`（原版「启智训练台」便携版功能基线）
>
> 对照对象：当前 Android 工程 `xingmou-app`，核对时间：2026-09-25。
>
> 状态含义：
> - **已完成**：安卓端已有可用实现，并有单元测试或仪器测试支撑。
> - **部分完成**：已有模型、规则、骨架或简化演示，但与原版完整功能仍有明显差距。
> - **未开始**：当前代码没有可运行实现。
> - **架构裁剪**：原版依赖浏览器/本地后端/机构服务，当前单机安卓方案暂不迁移；若产品范围不变，不作为近期缺陷，但要保留后续扩展设计。

## 一、结论摘要

当前安卓端不是原版功能的完整等价迁移，而是一个已经完成安全 Agent 基础、核心训练闭环和三端工作台的最小可验收版本。

建议团队按以下优先级补齐：

| 优先级 | 目标 | 主要缺口 |
|---|---|---|
| P0 | 从演示版变成可用产品 | 儿童档案、账号/权限、六域与训练目录、真实课程训练、数据持久化接线、同意管理 |
| P1 | 恢复原版核心体验 | 基线评估、训练地图、兴趣/奖励、完整 AI 方案、家长任务、专业临床工作流、报表 |
| P2 | 恢复专业与机构能力 | 扫描 OCR 导入、量表目录、12 方法库、治理工作台、数据导出/删除/共享、审计运营指标 |
| P3 | 上线级 AI 与质量 | 服务端 AI 网关、真实 DeepSeek 联调、模型指标、离线/超时/费用控制、无障碍深测 |

## 三、当前最影响产品可用性的 12 项缺口

1. 固定 `child-demo`，没有儿童档案、用户身份和授权关系，无法支持真实多儿童使用。
2. 儿童端只有一个演示题型，尚未成为 22 模块/20 关课程训练产品。
3. 没有首次基线，训练起点和六域能力画像无法真实生成。
4. `TaskWhitelist` 只有 8 个示例任务，缺原版 22 模块的完整内容资产。
5. 家长端是“观察→检索建议”页面，缺家庭任务、打卡、日记和陪练指导。
6. 专业端能审核固定草案，但缺完整临床工作流和正式签署信息。
7. 没有量表目录和 12 方法库，专业端知识支持不足。
8. 没有训练报表和可视化，无法直观看到趋势与模块表现。
9. 同意、导出、删除、共享等数据权利尚未形成可操作闭环。
10. 登录/RBAC/会话/失败锁定未实现，三端切换目前是本地 UI 切换而非真实权限隔离。
11. DeepSeek 客户端虽存在，但真实网关没有接入 ViewModel；且 APK 内置长期 Key 不适合生产。
12. 机构治理、批量 OCR 导入和后端同步缺失，无法支撑机构部署与运营。

## 四、已完成能力边界

当前可以稳定演示的能力：

- 儿童、家长、专业三端 Compose 工作台切换。
- 儿童端图片配对演示、连续失败暂停、恢复、安全停止和 TTS。
- 家长观察输入、风险路由、已审核本地知识检索、来源展示和安全免责声明。
- 专业端过程分析、数据充分度、方案草案、确认/激活/退回审核状态机。
- Agent 工具白名单、端口授权、最大步数、幂等、事件闭环、脱敏上下文和确定性降级。
- Room 数据持久化、1→2 迁移、红队测试、Compose UI 测试和 Room 仪器测试。

这些能力足以作为阶段性 Demo 和安全架构样板，但还不足以宣称“完成原版功能迁移”。
